Maturity

What a first release means here

DocFacts was tested against six real documentation pairs — ESLint, Jest, Ruff, Prettier, Vitest and uv. That run produced six confident false findings and about twenty-five noisy ones, and every one was a defect in DocFacts rather than in the documents.

All seven underlying bugs are fixed and pinned by regression tests. The useful part is what it says about confidence: a suite of 2,600 synthetic tests had found none of them, because the fixtures were written by the same person who wrote the parser. Six curl commands found them in an afternoon.

So: expect it to work on documentation shaped like those projects, and expect surprises on documentation shaped differently. A reference it reads wrong is the single most useful bug report you can send.

Known gaps

  • A fabricated status code in a table under a heading that does not mention codes is not detected. That scoping exists because without it a table of flag values was read as undocumented exit codes and flagged correct work.
  • A fabricated subcommand whose name is a common English word may be missed — traded deliberately against a much more common false positive.
  • Inference is heuristic and sensitive to formatting. The report prints what it inferred, before any finding, so a wrong reading is visible rather than silent.

DocFacts

MIT licensed. Reads two local files, prints a report. No network code, no dependencies.

A clean DocFacts report is not a guarantee that a document is correct. It means nothing in it contradicted the supplied reference in the specific ways the tool checks.
